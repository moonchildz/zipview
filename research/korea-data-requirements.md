# 한국 전역의 창문별 주거 전망 서비스를 위한 데이터 목록

작성일: 2026-09-10. 대상: 주소와 동·호를 입력하고 평면의 창문을 선택하면 해당 위치의 구조와 전망을 보여 주는 서비스.

이 문서는 수집 요구사항과 설계 제안이다. 전국 데이터를 이미 확보했거나 아래 기관의 모든 자료를 내려받을 수 있다는 뜻이 아니다. 공식 웹 설명·검색 수록 본문과 기존 프로젝트 조사 기록을 검토했으며, 이번 작업에서는 인증 API 호출, 전국 다운로드, 제공기관 협의 또는 현장 검증을 하지 않았다.

## 1. 핵심 결론

전국 공통의 외부 환경 데이터와, 단지별 세대·창문 배치 데이터를 결합해야 한다. 위성사진 또는 평면도 한 종류만으로는 동·호별 창문 시점을 확정하지 않는다.

필수 연결은 `주소 -> 실제 건물 -> 층/세대 -> 적용 평면 버전 -> 세대 배치 변환 -> 창문 -> 관찰 위치 -> 주변 환경`이다. 외부 제공기관의 ID는 내부 ID와 별도로 관리하고 서로 다른 데이터의 연결 근거를 남긴다.

현재 시범의 조사 기록에는 수동으로 읽은 현관·공용 코어 앵커, 도면 비례 창 폭, OSM 외벽 투영, 추정 층고와 부분별 높이가 기록되어 있다. 이를 전국 공통 정답으로 재사용하지 않는다. [기존 세대·창문 조사 기록](gyeonghuigung-xi/unit-layout-research.md), [지면 영상 구현 기록](satellite-ground.md).

## 2. 수집 목록

## 3. 한국의 수집 경로와 확인 범위

### 주소와 단지 목록

- 주소기반산업지원서비스의 주소·건물 데이터와 상세주소 기능을 검토한다. 공식 도움센터는 건물 단위 도형과 주소 기준 도형의 집계 단위가 다름을 설명한다. 따라서 같은 주소의 여러 동을 하나의 건물로 합치면 안 된다. [공식 도형 구분 안내](https://eng.juso.go.kr/addrlink/qna/qnaDetail.do?bulletinRefSn=132903&noticeMgtSn=132903&noticeType=QNA).
- 상세주소의 동·층·호 검색 기능이 있어도 실내 세대 경계와 창문 좌표가 제공된다는 뜻은 아니다. 이번에 특정 단지의 응답 완전성은 검사하지 않았다. [공식 상세주소 API 답변](https://m1.juso.go.kr/addrlink/qna/qnaDetail.do?bulletinRefSn=134892&noticeMgtSn=134892&noticeType=QNA).
- K-apt 기본정보는 가입 단지의 주소·동수·세대수 등 단지 속성에 활용할 후보다. 이 목록을 국내 모든 주택의 완전한 목록으로 간주하지 않고 건축물 자료와 누락을 대조한다. [전국공동주택표준데이터](https://www.data.go.kr/data/15096285/standard.do?recommendDataYn=Y).

### 건축 속성과 도면

- 건축HUB 건축물대장 API 설명에는 표제부·층별개요·전유부·면적 등 속성정보가 제시되어 있다. 주택인허가 API 설명에는 동별·층별·호별 개요가 제시된다. 이 설명만으로 세대 경계 폴리곤·창문 좌표 제공을 확인할 수는 없다. [건축물대장 공식 메타데이터](https://www.data.go.kr/catalog/15134735/openapi.json), [주택인허가 공식 메타데이터](https://www.data.go.kr/catalog/15136560/openapi.json).
- 건축HUB에는 배치도 검색과 도면파일 식별 항목이 있다. 전국 모든 아파트의 층별 평면·창호도까지 공개된다는 근거는 아니며, 이번에 단지별 도면 결과를 내려받지 않았다. [도면정보 배치도](https://www.hub.go.kr/portal/opn/tyb/idx-batch-flrpln.do).
- 실제 수집 후보는 건설사·시행사·설계사·관리주체가 보유한 분양자료와 준공도면, 이용허락을 받은 소유자 제공 자료다. 확보 가능성과 재사용 권한은 각 보유자에게 확인해야 한다. 이는 이번에 체결한 제휴가 아니라 확보 경로 제안이다.
- 세움터 안내는 소유자가 아닌 사람의 현황도 발급에 증빙과 승인 절차가 필요하다고 설명한다. 대장 속성 조회를 임의 세대 내부 도면의 무제한 일괄 수집으로 확대 해석하지 않는다. 이번 확인은 검색에 수록된 공식 안내 본문이며 발급 절차를 수행하지 않았다. [세움터 발급안내](https://www.eais.go.kr/moct/bci/aaa01/BCIAAA01V01).

### 지형·도로·영상·외부 건물

- 도로명주소 전자지도 소개에는 건물·건물군·도로구간·실폭도로 등이 제시된다. 실폭도로는 추정 폭을 대체할 수 있는 수집 후보지만 단지 내부의 모든 보행로·화단·높이 정보가 들어 있다는 뜻은 아니다. 신청·제공 조건과 최신 데이터 구조는 별도 확인한다. 직접 열린 페이지에서 상세 소개가 빠져 있어 이번 근거는 공식 포털의 검색 수록 설명이다. [행정안전부 전자지도 제공 설명](https://www.data.go.kr/dataset/3033566/openapi.do?lang=en).
- 국토지리정보원 자료는 수치지도·항공/정사영상·지형 및 3D 기본도 후보다. 2025년 공식 브로슈어의 검색 수록 본문은 전국 1:5,000 지도, 도심 1:1,000 지도, 건물 높이와 지형을 포함한 3D 기본도를 설명한다. PDF 직접 열기는 실패하여 전체 문서는 검토하지 못했다. 전국 동일 해상도·최신성·다운로드 권한은 이번에 확인하지 않았다. [국토지리정보원 2025 브로슈어](https://www.ngii.go.kr/lib/file/2025_KOR-%EA%B5%AD%ED%86%A0%EC%A7%80%EB%A6%AC%EC%A0%95%EB%B3%B4%EC%9B%90%20%EB%B8%8C%EB%A1%9C%EC%8A%88%EC%96%B4.pdf).
- DEM 메타데이터 CSV는 높이 래스터 자체가 아니다. 필요한 것은 실제 지형 자료와 그 품질·좌표 정보다. [수치표고 기본 메타데이터 설명](https://www.data.go.kr/data/15067632/fileData.do?recommendDataYn=Y).
- 브이월드·지자체 3D 자료·허가된 측량 및 촬영 자료는 추가 검토 후보다. 이번 브이월드와 국토정보플랫폼 직접 열기는 실패했고, 현재 지역별 3D 제공 범위와 원본 재사용 조건은 검증하지 못했다. 이미 확보된 데이터로 계산하지 않는다.

### 표시용 API와 보유 원천 데이터의 분리

Google Map Tiles 정책은 표시용 사용과 달리 이미지 분석·기계 해석·객체 검출·지리정보 추출 등을 허용하지 않으며 저장에도 제한을 둔다. 따라서 Google 타일을 수집해 창문·건물 DB를 추출하거나 AI 입력으로 자유롭게 재사용하는 방식을 기본 수집 전략으로 두지 않는다. 적용 계약과 허락 범위를 별도로 확인한다. [Map Tiles 공식 정책](https://developers.google.com/maps/documentation/tile/policies).

영상 표시, 원본 저장, 벡터화/3D 재구성, 텍스처 제작, AI 입력·학습, 결과물 공개·판매 권한을 각각 기록한다. 출처 표기만으로 모든 이용 권한이 생긴다고 간주하지 않는다. 사용자 제공 자료도 업로더의 허락 권한과 개인정보 처리를 검토한다.

## 4. 반드시 직접 구축할 연결 데이터

아래는 외부 API의 실제 응답 스키마가 아니라 내부 저장 모델 제안이다.

| 객체 | 중요한 필드 |
| --- | --- |
| 건물 식별 연결 | 내부 건물 ID, 제공자별 ID, 단지/필지 연결, 주소 이력, 동 명칭, 연결 근거·상태 |
| 세대 인스턴스 | 건물 ID, 실제 층/호, 라인, 적용 평면 ID와 버전, 세대 경계, 층 구간·예외 |
| 평면의 공간 배치 | 원자료 축·단위, 도면-지도 기준점, 변환 행렬, 반사 여부·회전·이동·축척, 검증 잔차 |
| 수직 기준 | 층별 바닥 표고, 원자료 수직 기준, 지반·주차장 데크와의 관계, 추정 방식·오차 |
| 창문 | 세대 ID, 방 ID, 로컬 개구부 경계, 폭·높이·창턱, 바깥 방향, 발코니/난간, 파생 세계좌표 |
| 관찰 위치 | 창문 ID, 실내 위치·창에서의 거리, 해당 바닥에서의 눈높이, 방향·상하각·화각 |
| 환경 객체 | 형상·높이·재질, 이름, 시점, 출처, 지형/건물/수목 구분, 표시 수준 |
| 검증 관측 | 대상 창·사진, 촬영 자세, 실측 기준, 예상/관측 차이, 검토자·검토일, 동의·공개 범위 |

- 좌우 판정은 비대칭 근거를 요구한다. 현관과 코어, 인접 세대, 특징적인 발코니 등의 대응을 보존한다. 대칭이거나 근거가 상충하면 `unknown`으로 둔다.
- `1004호 = 10층 4라인` 같은 문자열 규칙만으로 확정하지 않는다. 반복층에 적용할 수 있는 자료와 예외층 자료를 분리한다.
- 건물 총높이와 층수만으로 각 층의 바닥 높이가 확인되었다고 표시하지 않는다. 눈높이 1.5m는 서비스 기본 설정이며 실측값이나 모든 사람의 평균으로 저장하지 않는다.
- 평면 좌표와 지도 좌표, 지도 수평 기준과 높이 기준을 따로 보존한다. 지붕·수목 높이가 포함된 표면 모델을 순수 지반으로 사용하지 않도록 데이터 종류를 명시한다.
- 자료가 허용하는 해상도 이상의 좌표 정확도를 주장하지 않는다. 파생 좌표는 원본 자료와 변환 버전에 연결해 재계산할 수 있게 한다.

## 5. 수집 및 출시 순서 제안

1. 전국 주소·건물·주거용도·단지 식별 목록을 만든다. 제공기관 ID 연결과 누락·중복 검토를 먼저 수행한다.
2. 외부 환경을 지역별로 구축한다. 건물 외곽·높이, 지형, 실제 도로 경계, 허용된 영상의 지역/시점/해상도 목록을 만든다.
3. 자료 권한을 확보한 서로 다른 유형의 단지부터 세대 연결을 구축한다. 경사지, 필로티, 판상형/타워형, 같은 타입의 반전, 층별 예외가 있는 표본을 포함한다.
4. 단지마다 배치도 + 동호·타입표 + 층 전체 평면 + 세대 평면 + 단면 + 입면/창호 자료를 한 묶음으로 수집한다. 누락 항목을 명시한다.
5. 같은 라인의 저층/고층, 반전되는 이웃 라인, 전면/후면 창의 실제 사진으로 검증한다. 주민의 답변은 정답 데이터의 한 출처로 관리하되, 모든 신규 세대의 필수 수동 입력으로 만들지 않는다.
6. 검증된 반복층·같은 도면 버전에만 확장한다. 대칭·불일치·오래된 자료는 수동 검토 대상으로 남긴다.
7. 외관·수목·포장 재질과 계절 표현을 보강한다. AI 실사화 결과는 형상·가림을 바꾸지 않는지 별도로 검사하고 실제 촬영 증거로 사용하지 않는다.

정밀화 범위는 단지 경계가 아니라 실제 시야의 가림 물체로 정한다. 주변 주민센터처럼 단지 밖이더라도 가까이 크게 보이는 건물은 우선 확보하고, 먼 배경은 낮은 상세도로 처리할 수 있다.

## 6. 전국 지원과 정확도 표시

다음은 서비스 등급 제안이다. 하나의 종합 점수로 숨기지 말고 세대 매칭·창 좌표·높이·주변 가림·외관·최신성의 상태를 따로 표시한다.

| 제공 수준 | 필요한 근거 | 사용자에게 할 수 있는 설명 |
| --- | --- | --- |
| 주소/건물 조회 | 주소와 건물 연결 | 해당 건물 및 주변 환경 조회. 특정 호수의 창 전망은 미지원 |
| 창문별 추정 | 세대·평면·배치·높이 연결, 추정 근거 | 자료 기반 창문 시점 후보. 검증되지 않은 항목 표시 |
| 검증된 창문 전망 | 해당 연결과 지형·가림의 독립 검증 | 검증한 범위·시점·오차를 명시한 전망 |
| 실사에 가까운 표현 | 위 항목 + 충분한 외관·지면·수목 자료 | 사진 질감과 기하 정확도를 구분. 생성물은 생성물로 표시 |

진행률은 확보한 파일 수가 아니라 전체 대상 대비 건물 식별률, 동호-타입 연결률, 창문 배치 가능률, 독립 검증률, 최신 데이터 비율로 측정한다. 누락·분모·기준 시점을 함께 기록한다.

## 7. 세계 확장을 위한 원칙

국가별 주소·대장·지도 제공자는 교체 가능한 입력으로 두고, 건물·층·주거 공간·창문·환경·관측 모델은 공통으로 유지한다. 단지/동/라인이 없는 집도 표현할 수 있어야 한다. 층과 호는 별도 식별자로 두고 숫자 계산에 의존하지 않는다. 국가·제공자별 수평/수직 좌표계, 단위, 층 표기, 이용권한, 개인정보 요구를 별도로 매핑한다.

가장 중요한 자체 자산은 단순한 평면도 이미지 모음이 아니라, 이용권한과 검증 근거가 붙은 `실제 집 -> 평면 버전 -> 공간 배치 -> 창문 위치` 연결 데이터다.
