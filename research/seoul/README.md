# 서울 수집 카탈로그와 반전 검증

수집·검사일: 2026-09-10. 서울 범위의 주소/단지 목록, 외부 환경, 확보한 도면 묶음을 로컬 SQLite로 구축했다. **서울 모든 아파트의 창문 전망을 지원하게 된 것은 아니다.** 외관·재질·AI 실사화 작업은 이번 범위에서 제외했다.

추가 조사: 2,888건은 2026년 초 국토교통부 공시가격 조사 대상 서울 아파트 9,528단지 대비 **단순 개수 비율 30.31%**다. 유형·시점·단지 구분 차이가 있으므로 정확한 수록률로 간주하지 않는다. [원문 확인과 계산 내역](coverage-comparison.md).

OSM 요청은 223,179,474바이트를 받은 뒤 서버가 `Query timed out in "print" ... after 399 seconds`를 반환했다. 완전한 JSON으로 들어온 개별 형상만 명시적 부분 수집 옵션으로 등록했다. 질의 전체는 **미완료**이며 `queryComplete: false`와 오류 원문을 보존한다. 변환 과정에서 지원하지 않거나 불완전한 형상 61개를 제외했다. `boundaryValidated`는 경계 폴리곤의 변환 성공 여부일 뿐 측량 정확도 인증이 아니다. 서울 경계 밖 가림 건물까지 완전하게 수집한 것도 아니다.

건물 높이와 도로 폭이 없으면 `null`이다. 층수·차로 수를 실제 높이·폭으로 바꾸지 않았다. 단지 주소와 OSM 건물 사이의 가까운 위치만으로 동 번호를 확정하지 않는다. 운영 연락처·보험 식별정보 등은 정규화 단지 목록에서 제외했다. 서울시 `HH_TYPE`은 분양/임대 등의 구분이며 세대 평면 타입이 아니다.

- [Mapzen/Tilezen Terrain Tiles](https://registry.opendata.aws/terrain-tiles/): 실제 PNG를 디코딩해 크기·해시 검사. [원자료별 출처·이용조건](https://github.com/tilezen/joerd/blob/master/docs/attribution.md)을 별도 기록했다. 타일마다 원천 측량 정확도나 수직 기준을 검증한 것은 아니다.
- [LH 서울대방 정정 공고](https://apply.lh.or.kr/lhapply/apply/wt/wrtanc/selectWrtancInfo.do?aisTpCd=42&ccrCnntSysDsCd=03&mi=1026&panId=2015122300020297&uppAisTpCd=39): 2026-06-29 공고, 2027-09 입주 예정 표기. [단지 배치도](https://apply.lh.or.kr/lhapply/lhFile.do?fileid=67457653), [동호배치표](https://apply.lh.or.kr/lhapply/lhFile.do?fileid=67457654), [55AH/55AL 치수 병기 평면](https://apply.lh.or.kr/lhapply/lhFile.do?fileid=67457871)을 각각 이미지로 열어 확인했다. 원본 도면은 재배포·상업 사용 권한 미확인으로 로컬 참고 전용이다.

서울대방 동호표를 판독한 [범위 데이터](daebang-unit-ranges.json)는 101동 131개, 102동 52개, 103동 100개다. 필로티와 상층부 비어 있는 라인을 제외했다. 55AS 같은 세부형의 호별 대응, 74A/74B 세대 도면, 준공 변경은 미확인이다. 분양 타입 이름과 실제 도면 버전·좌우 변형은 별개로 저장한다. 안내 PDF도 다운로드했지만 파일이 잘려 PDF 파싱에 실패했으므로 확보·검토 완료 자료로 세지 않았다. SH 사이트는 접근 제한으로 이번 수집에 포함하지 못했다.

기존 자료는 [신촌 조사 기록](../sinchon-prugio/README.md), [경희궁자이 조사 기록](../gyeonghuigung-xi/unit-layout-research.md)을 연결했다. 이번에 세 단지 전체의 세대 연결을 다시 검증하거나 준공도면을 확보한 것은 아니다. Google 타일의 추가 요청·추출·AI 입력은 하지 않았다.

## 반전 오류 방책

기존 현관-코어의 상대 방향 비교는 가설을 세우는 데만 쓰고, 독립 정합을 통과한 배치와 분리했다. 경희궁자이 기존 화면과 후보 좌표는 유지하되 `반전 검증 보류`, `orientationAutomaticPlacement=false`로 표시한다. 지금 원본과 반전 중 어느 쪽이 실제와 일치하는지를 새롭게 확정한 것은 아니다.

새 검사기는 다음 조건으로 설계했다.

1. 먼저 같은 동·층·호·도면 버전임이 자료에서 연결되어야 한다. 세대 평면과 그 세대가 포함된 층 전체 평면 등 서로 다른 근거가 필요하다. 단지 지붕 배치도만으로 실내 기준점을 대신하지 않는다.
2. 현관, 주방 개구부, 외벽 모서리, 비대칭 발코니 끝처럼 **이름이 고정된 대응점 최소 4개**를 입력한다. 좌우 후보마다 점 이름을 서로 바꿔 점수를 높이는 매칭은 허용하지 않는다.
3. 비공선 3개 이상으로 회전·균일 축척·이동을 계산하고, 반전 없음/있음 두 후보를 비교한다. 이미지 Y축 아래 방향과 지도 북쪽 위 방향을 먼저 정규화해 축 변환을 물리적 좌우 반전으로 오해하지 않는다.
4. 계산에 쓰지 않은 별도 검증점 1개 이상이 허용 오차 안에 들어와야 한다. 허용 오차는 대상 좌표의 단위로 두 문서 판독 오차를 반영해 명시해야 하며, 통과할 때까지 임의로 키우지 않는다.
5. 검증점 충돌, 대응점 부족·중복·거의 일직선, 원본/반전 점수 차이 부족이면 `mirrored: null`과 `automaticPlacement: false`를 반환한다.

이는 기하 검사이며 자동 도면 인식이나 현장 검증 결과가 아니다. 대응점의 명칭·좌표가 잘못 판독되면 잘못된 정합도 통과할 수 있으므로 별도 검토자와 허가된 현장 관측을 통한 검증이 필요하다. 비율이 심하게 왜곡된 스캔본은 이 검사에서 보류하고 먼저 도면 보정을 해야 한다. `automaticPlacement: true`도 현장 검증 완료를 뜻하지 않으며 `verified`는 계속 false다.

현재 자료 묶음에는 독립 기준점이 없으므로 모두 검증 보류다. 다음에 우선 확보할 자료는 **층 전체 평면에 호수·현관·공용 코어·비대칭 외벽이 함께 나온 도면**이다. 같은 이미지의 복제본이나 사용자에게 반전 스위치를 고르게 하는 것으로 대체하지 않는다. [입력 템플릿](registration-template.json)의 빈 좌표를 추정값으로 자동 채우지 않는다.

## 저장과 실행

프로젝트 루트에서 Node 24로 실행한다. 키를 코드에 넣지 않는다. 이번에 수집한 공개 내보내기·이미지·지형에는 Google/Kakao/서울시 API 키를 사용하지 않았다.

```powershell
npm run query:seoul -- search "경희궁자이"
npm run query:seoul -- unit seoul-daebang-planned 101 201
npm run query:seoul -- nearby seoul:A10027118 300
npm run query:seoul -- coverage
npm run register:plan -- research/seoul/registration-template.json
npm run verify:seoul
```

- `generated/seoul.sqlite`: 단지 검색, 경계 상자 공간 검색, 도면 묶음, 동호 연결, 출처/커버리지. 창문별 3D 장면을 자동 생성하는 DB가 아니다.
- `generated/complexes.json`, `packages.json`, `coverage.json`: JSON 내보내기.
- [coverage-summary.json](coverage-summary.json): 저장소에 남길 수집 개수·결측·출처·해시 요약.
- `raw/`: 내려받은 원본과 URL/요청/시각/SHA-256 메타데이터. 큰 원본과 권한 미확인 도면은 Git 제외.
- `generated/`: 로컬 생성 DB와 내보내기. 원본을 확보한 뒤 `npm run build:seoul`로 재생성한다.

공개 수집기는 `npm run collect:seoul -- apartments`, `-- daebang-site`, `-- daebang-units`, `-- daebang-plan`과 `npm run collect:seoul-terrain`이다. OSM 전체 요청은 서버 시간제한으로 실패한 상태이므로 그대로 반복하지 말고, 후속으로 적절한 지역 추출본 또는 분할 수집을 준비해야 한다. 기본 수집기는 오류 응답을 거부한다. 이미 받은 부분 JSON을 검사 후 보관하는 명시적 명령은 다음과 같고, 완료 상태를 false로 유지한다.

```powershell
node scripts/collect-seoul.mjs osm verification/seoul-osm.json --allow-partial
```

`nearby`는 경계 상자 후보 검색으로 정확한 원형 반경·동 식별이 아니다. 결과 상한과 부분 수집 경고를 반환한다. 미등록 호수에는 다른 평면을 대신 반환하지 않는다. 등록 호수도 공간/고도 검증 전에는 `viewReady: false`다.

## 남은 수집 작업

- 공식 건물/주소 식별자와 개별 동 외곽의 교차 연결, 수록되지 않은 서울 공동주택 확인.
- 누락된 OSM 부분 보완과 공식 건물 높이·실폭도로·고해상도 지형 확보. 주변 건물 높이·지반이 없으면 조망의 가림을 정확히 계산할 수 없다.
- 다른 구조 유형 단지의 층 전체 평면·세대 타입·반전·예외층 연결과 이용허락.
- 층 바닥 표고·필로티·단차·창호 치수와 독립 정합 기준점. 이 항목이 채워지기 전에는 자료 묶음을 검증 완료로 승격하지 않는다.

검사는 원본 5개 해시, 지형 PNG 36개, SQLite 무결성·개수·결측 상태를 대조한다. 별도 단위 테스트는 회전/축/반전 조합, 독립 검증점 충돌, OSM 중정 폴리곤과 실제 스트리밍 변환, 동호표 예외층을 검사한다. 브라우저 검사는 과금 API를 모의 응답으로 대체하며 실제 위성영상 정확도 검사가 아니다.
