## 로컬 주소 조회 검증 (2026-09-11)

첫 화면 `/`는 이제 주소 조회다. 기존 공간 데모는 `/?site=sinchon`, `/?site=xi`로 유지한다.
저장된 도로명·지번 주소와 서울/자치구를 생략한 주소를 조회할 수 있다. 지번 별칭은 원자료의 법정동과 완전한 숫자 지번 필드만 사용하며, 임의의 주소 메모를 해석하지 않는다. 같은 주소에 여러 단지가 있으면 선택을 요구한다. 주소만 입력하면 단지의 평면도 목록을, 동호수 연결이 있으면 해당 평면도를 먼저 표시한다. 라인 판독 후보와 확정되지 않은 방향은 계속 별도로 표시한다.

보유 평면도는 외부 요청 없이 조회한다. 주소만 있는 단지는 기존 수집기를 호출하며, 수집 실패가 기존 자료를 지우지 않는다. 동일 주소의 서로 다른 공급자 ID도 덮어쓰지 않는다. 로컬 preview 서버 역시 최신 인덱스를 읽으므로 수집 후 새로고침해도 결과가 유지된다.

npm.cmd run verify:addresses
$env:TEST_BASE_URL='http://127.0.0.1:5174'

## 주소에서 시작하는 자동 수집

```powershell
npm.cmd run pipeline:addresses -- "서울 종로구 송월길 99"
npm.cmd run pipeline:addresses -- --file research/linkage/addresses.example.json
```

이 명령은 수집 후 공통 인덱스까지 갱신한다. 주소마다 사람이 사이트를 열거나 연결표를 작성하지 않는다. `collect:addresses`는 수집만, `build:linkage`는 이미 저장한 자료의 인덱스 생성만 수행한다. `/?site=catalog`의 주소 입력도 미수집 단지이면 같은 코드를 호출한다. 기존 데모의 조회 버튼도 공통 조회로 이동한다. 동·호는 선택 입력이며 한 줄에 `주소 209동 1201호`도 허용한다.

1. KB 공개 웹 검색 응답에서 단지 후보와 도로명/지번 주소·공급자 ID를 읽는다. 전국 검색이며 서울 목록에 없는 주소도 요청한다. 여러 후보이면 자동으로 첫 단지를 선택하지 않는다.
2. 공개 단지 HTML의 JSON을 파싱해 **모든 공급자 평형 ID**, 전용/공급면적, 타입 표기, 기본/확장 평면도 URL을 추출한다. 스크립트를 실행하거나 면적만으로 타입 ID를 합치지 않는다.
3. 표시 가능한 평면도 이미지를 내려받는다. 면적 정보만 있고 그림이 없는 타입도 삭제하지 않고 이미지 부재를 표시한다.
4. 공개 동 목록과 각 동의 호 목록을 읽어 **공급자의 면적 ID**로 연결한다. 기존 배치표와 충돌하면 덮어쓰지 않는다. 동호수표를 반환하지 않는 단지는 평면도 목록만 제공한다.
5. 출처·수집 시각·캐시 해시·실패 단계를 저장하고 공통 인덱스를 갱신한다. 방향·높이가 없어도 평면도는 열람할 수 있다.

구현: `scripts/address-pipeline.mjs`, `scripts/kb-public-source.mjs`, `scripts/address-server.mjs`. 개발/로컬 preview 서버에 수집 API가 포함된다. 정적 파일만 배포하면 새로운 주소의 실시간 수집은 실행되지 않으므로 Node 서버가 필요하다. 원본 그림은 수집기의 로컬 다운로드이며 공개 재배포 권한을 확인한 자료라는 뜻은 아니다.

공개 페이지/검색/동호수 데이터는 7일, 이미지 캐시는 30일 재사용한다. `--refresh`로 갱신할 수 있고 `--max-requests 150`처럼 실행당 요청 상한을 지정한다(기본 90, 최대 200). 403/429는 자동 우회·재시도하지 않는다. 실패한 주소가 있어도 성공한 주소는 저장하고 다음 실행에서 캐시를 재사용한다. 개인정보·시세·중개사 연락처는 정규화 결과에 넣지 않는다.

실행 검증(2026-09-11 KST): 예제 세 주소를 같은 코드로 처리했다. 자이 19개 평형/28개 기본·확장 이미지, 신촌 20개 평형/28개 이미지/923개 호수, 해운대아이파크 199개 평형/이미지 0개/1,631개 호수. 최초 외부 요청 84회, 재실행 외부 요청 0회·캐시 84회. 자이 동호수 목록은 공급자가 반환하지 않아 기존 102개 후보에서 확대되지 않았다. 이는 임의 이미지 배치도를 읽는 OCR/시각 모델 파이프라인이 아니며, 공개 구조화 데이터가 없는 연결을 생성하지 않는다.

공급자 페이지: https://kbland.kr/se/c/36262 · https://kbland.kr/se/c/30737 · https://kbland.kr/se/c/16105. 서울시 전체 단지 JSON도 이번 실행에서 재수집했다. 원본은 로컬 `research/seoul/raw/apartments.json`이다.

`providers/kb/*.json`은 추출 결과, `downloads/kb/`는 평면도, `cache/`는 재실행 캐시, `generated/address-run.json`은 배치 실행 보고서다. 개발 화면에서는 새 주소 수집 후 즉시 갱신한다.

`npm run build:linkage`는 **현재 PC의 자료만** 읽어 공통 인덱스와 누락 보고서를 재생성한다. 네트워크 수집이나 세대마다 AI 호출을 하지 않는다. `npm run dev`, `npm run build` 전에 자동 실행한다. 실행 중 자료를 추가했다면 명령을 다시 실행하고 전체 조회 화면을 새로고침한다.

웹: `/?site=catalog`. 명령줄:

```powershell

npm.cmd run query:linkage -- unit "경희궁자이 2단지" 211 1201
npm.cmd run query:linkage -- unit "북아현로1길 50" 204 802

```

## 입력과 연결 기준

- 신촌: 기존 `src/data.js`의 판독 세대와 8개 타입 전부. 비교용 두 세대는 실제 세대 근거와 별도 집계한다.
- 경희궁자이: `src/xi-unit-registry.js`의 전체 범위를 펼쳐 타입과 방향·반전 후보를 연결한다. 후보는 확정 데이터가 아니다.
- 서울대방: `research/seoul/daebang-unit-ranges.json`의 전체 범위와 예외층을 그대로 사용하고 동별 총수를 대조한다. 55AS 세부형, 74형 도면, 준공 결과는 추정으로 채우지 않는다.
- 각 장면의 단지 경계 출처와 동 번호를 함께 사용한다. 신촌의 경계는 1·2단지를 포함하므로 2단지 동 목록으로 추가 제한한다. 같은 이름의 다른 단지 동은 연결하지 않는다.
- 서울 전체 `raw/apartments.json`, `generated/complexes.json`, `generated/seoul.sqlite`가 있으면 읽는다. 없으면 기존 수집 보고서의 숫자를 현재 데이터처럼 사용하지 않고 `input-missing`을 남긴다.
- `research/`와 `mapinfo/`의 모든 로컬 파일을 목록화한다. 단지별 폴더의 문서는 그 단지에, 북아현 수치지도는 신촌 환경 자료에 연결한다. 이는 수치지도의 모든 객체가 특정 세대의 지반이라는 뜻이 아니다. 광역/미배정 자료는 별도 보고한다. ZIP 내부는 기존 수치지도 처리기가 만든 장면·보정 자료를 참조하며 이 단계에서 재측량하지 않는다.

식별자는 `(단지 ID, 동, 호)`다. 주소 공백과 서울특별시/서울 표기를 정규화하되 일부 문자열 유사도나 가까운 좌표만으로 단지를 확정하지 않는다. 중복 주소는 후보를 모두 돌려준다. 층·라인 범위를 펼칠 때 중복과 잘못된 범위를 거부하며, 서로 충돌하는 세대 근거는 보존하고 미리보기를 막는다. 평면도 파일, 외곽, 방향, 층 표고, 준공 확인 여부는 별도 필드다. 현재 모든 `viewReady`와 `verified`는 false다.

## 자료 추가

기존 입력 파일을 확장하거나 `research/linkage/packages/*.json`에 아래 형태의 패키지를 추가한다. UI/조회 코드에 세대별 분기를 추가할 필요가 없다. 서로 다른 단지는 고유 ID를 사용한다. 기존 단지에 세대/타입만 추가할 때는 `complexes`를 생략한다. 타입별 원본은 한 번만 등록하고 `ranges`가 같은 층·라인에 재사용한다. 층별 예외는 범위를 분리하거나 명시적 `units`로 등록한다. 기존 자료와 충돌하면 덮어쓰지 않고 보고한다.

```json
{
  "complexes": [{"id":"sample-complex","name":"예시 아파트","address":"예시 주소","aliases":[]}],
  "buildings": [{"complexId":"sample-complex","building":"101","geometry":null}],
  "plans": [{"complexId":"sample-complex","id":"84A","file":"research/example/84A.jpg","source":"원본 출처"}],
  "ranges": [{"complexId":"sample-complex","building":"101","firstFloor":2,"lastFloor":15,"lines":[1,2],"chartType":"84A","source":"동호수표 출처"}]
}
```

출력은 `generated/catalog.json`, `generated/report.json`이다. 검증이 끝난 스냅샷을 교체하며 같은 입력의 재실행 결과는 동일하다. 파일 부재/파싱 실패를 성공으로 숨기지 않는다. 이 파이프라인은 확보 자료의 연결을 자동화한다. 자료 자체에 없는 호수나 도면 방향을 만들어내는 기능은 아니다.
# 이미지 배치도 추출 (2026-09-11)

`npm run pipeline:addresses -- "서울 종로구 송월길 99"`는 공개 공급자 수집 뒤 등록된 이미지 배치도를 판독하고 조회 인덱스를 다시 만듭니다. 브라우저의 주소 수집 API에도 같은 단계를 연결했습니다. 이미지 단계만 실행하려면 `npm run extract:charts`를 사용합니다. 일반 빌드는 이미 내려받은 이미지에만 접근합니다.

`scripts/chart-image-reader.mjs`는 색상 범례와 숫자 글꼴 샘플을 사용해 원본 픽셀에서 라인 번호와 타입을 읽습니다. `*-chart-profile.json` 파일을 자동 발견하며, 문서별 동 영역·범례·글꼴 샘플 설정은 필요합니다. 임의의 배치도에서 이 설정까지 자동 생성하는 범용 OCR은 아닙니다. 동·라인별 타입 정답은 설정에 들어 있지 않습니다.

초기 글꼴 판독에서는 7개 라인만 채택했습니다. 후속 원본 검토에서 201~214동의 라인 번호 위치 60개를 수동 보정하고, 해당 좌표 주변의 원본 색상과 범례를 대조하여 현재 총 41개 라인 후보를 연결했습니다. 설정에는 번호와 위치만 기록하며 타입은 원본 색상에서 읽습니다. 수동 보정이 포함된 문서별 추출이지 범용 자동 OCR은 아닙니다. 색상 판별이 불안정한 위치는 계속 탈락시키며 209동 3라인도 미연결입니다. 210동 1·4라인처럼 여러 타입이 함께 표기된 위치는 층별 자료가 없으므로 제외합니다. `templateSimilarity`는 글꼴 비교 점수이며 정답 확률이 아닙니다.

결과는 `research/linkage/generated/charts/`에 원본 출처, 이미지·설정·판독기 해시, 판독 좌표, 탈락 이유와 함께 저장합니다. 원본 해시가 바뀌면 재보정이 필요하며 이전 결과를 재사용하지 않습니다. 이미지나 판독이 실패하면 해당 프로필은 실패 상태와 빈 결과로 갱신됩니다.

카탈로그의 `lineAssociations`는 확정 세대 연결인 `units`와 구분됩니다. 예를 들어 209동 1201호는 84A 원본 평면도를 보여주되 `image-line-candidate`로 표시합니다. 라인 그림으로 실제 호수 존재나 층별 예외, 방향·반전, 실내 3D 배치를 확정하지 않습니다. 별도 세대 연결 자료가 있으면 그 자료를 우선 사용합니다.

## 호수 전수 대조와 완료 기준

주소 검색 성공과 이미지 파일 검증만으로 호별 연결이 완료된 것은 아닙니다. `npm run verify:units`는 공급자 원자료의 모든 호수·평형 ID가 조회 인덱스에 남아 있는지, 등록 세대와 라인 후보가 실제 조회되는지 검사합니다. `npm run verify:units -- --require-complete`는 활성 자료 패키지 모두에서 자료상 총 세대 수와 호 목록이 일치하고, 모든 호수에 충돌 없는 타입과 평면도 이미지가 있을 때만 성공합니다. 라인 후보나 이미지 없는 타입을 완료에 포함하지 않습니다.
