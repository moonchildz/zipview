## 세대 연결과 3D의 검증 범위

주소를 단지 ID로 정규화한 뒤 동·호를 키로 도면 타입을 조회한다. 분양표에서 직접 판독해 등록한 세대만 결과를 반환하고, 등록되지 않은 호수에는 임의의 타입을 넣지 않는다.

분양표 기준 연결은 현 세대의 리모델링, 확장 여부, 좌우 반전, 정확한 방위각을 확인했다는 뜻이 아니다. 앱의 3D는 원본 도면을 수동으로 벡터화한 초안이며, 길이와 높이는 추정치다.

실제 전망 재현에는 동/세대의 지리 좌표, 회전/좌우 반전, 지반고, 층별 표고, 창호 치수, 주변 건물과 지형 데이터가 추가로 필요하다. 이번에 확보한 분양 조감도를 실제 전망으로 대체하면 안 된다.

소형 34/44/49/53㎡ 도면, 원본 고해상도 도면, 준공 변경 사항은 이번 수집본에 포함되지 않았다.

## 206동 높이 비교 시범 추가

- [59D 기본형 도면](images/59D.jpg)을 KB 페이지의 81D 공급형 이미지에서 추가 확보했다. 원본 URL과 주변 텍스트는 `outlook/59D-source.json`, 수집기는 `scripts/fetch-plan59.mjs`에 보관한다. 도면에는 치수 표기가 있으며, 하단 합산 폭 9.4m를 수동 모델의 축척 기준으로 사용했다.
- 배치표의 206동 4호 라인 타입은 59D로 판독했지만 504/1004 셀은 개별 확인하지 못했다. 이 두 호수는 사용자가 제안한 층 비교 시나리오로만 등록했다. 준공 세대 존재나 실제 창 위치/방위는 미확인이다.
- OSM 원본 요청: `https://api.openstreetmap.org/api/0.6/map?bbox=126.942,37.551,126.964,37.57`. `scripts/fetch-outlook.ps1`로 받아 XML 파서로 정리했다. 원본은 `outlook/osm.xml`, 정리본은 `outlook/osm.json`이다. Overpass 요청은 HTTP 406으로 실패하여 기본 Map API를 사용했다.
- 206동은 OSM way 777716407이다. 지도 태그에 높이 50m, 17층이 있다. 공인 실측치로 간주하지 않는다. 2,716개 건물 중 316개만 높이 태그가 있고, 나머지는 층수×2.9m 또는 용도별 9/15m 가정값이다.
- [Mapzen Terrain AWS 데이터](https://registry.opendata.aws/terrain-tiles/)의 Terrarium z12 PNG 25장을 확보했다. `scripts/prepare-outlook.mjs`가 RGB 고도를 복원하고 지형 격자와 건물 기초 표고를 생성한다. 랜드마크 추가에 맞춰 32km 폭의 513×513 격자(62.5m 간격)로 확대했다. 대지 단차/옹벽/실제 1층 표고를 재현하지 못한다.
- 초기 창 좌표 경도 126.954844, 위도 37.561200, 방위 78도는 방향 검토 후 폐기했다. 재검토본은 206동 외곽선의 인덱스 9~10 구간(남동쪽 외벽 후보) 중점에서 외측 0.8m에 시점을 둔다. 외벽 법선으로 계산한 방위는 약 123도다. 이 외벽을 4호 거실 전면으로 보는 것은 배치도 판독 가설이며 창의 정확한 위치와 방향은 실측하지 않았다. 이전 시점은 `previousWindow`에 보존한다. 5층과 10층은 동일 XY에 `지반 + (층-1)×2.9 + 눈높이`를 적용한다. 눈높이는 최초 1.6m에서 사용자 요청에 따라 기본 1.5m로 수정했고 0.8~2m 범위에서 조절할 수 있다.
- 전망 하단에 원본 배치도와 실제 렌더링 좌표를 공유하는 시선도를 추가했다. 원본에는 개략 위치를 표시하고, 지도 외곽선에는 회전/위치 보정에 동기화된 카메라 좌표와 화살표를 표시한다. 보정으로 카메라가 건물 내부에 들어가면 경고한다.
- 렌더링 데이터는 `outlook/scene.json`. 건물 외곽은 OSM 기여자 ODbL, 지형은 [원자료별 출처/조건](https://github.com/tilezen/joerd/blob/master/docs/attribution.md)을 따른다. 도면의 상업적 이용허락은 별도 미확인이다.
- 수목, 외벽 텍스처, 발코니 창틀, 약 2km 수집 범위 밖의 일반 건물은 미반영이다. 아래 랜드마크만 별도 추가했다. 실내 모델과 외부 전망은 별도 시점으로 제공하며 창을 통해 연결된 실내외 정합 모델은 아니다.

## 주변 사진과 도로/외관 표현 보강

[KB부동산 방문 게시글](https://kbland.kr/se/otd/286957), 게시자 깜찍한호랑이, 게시일 2023-12-07의 본문과 사진 7장을 확인했다. 1번과 6번 사진에서 출입구의 신촌푸르지오 2단지 표기를 확인했다. 2번/3번은 102동과 1단지 출입구가 보이므로 206동 외관 자료로 사용하지 않는다. 4번은 과선교 공사 가림막이며 현재 준공 상태를 나타내는 자료로 쓰지 않는다. 5번과 7번에서도 건물과 주변 길이 보이지만 206동 전면 도로라는 위치 정합은 확인하지 못했다.

- 사진은 `photos/kb-20231207-1.jpg`부터 `-7.jpg`까지 검토용으로 보관했다. 원본을 앱 재질로 복제하거나 배포 번들에 넣지 않았고 앱에서는 원 게시글로 연결한다. 재배포/상업 이용허락은 확인하지 못했다.
- 2단지 출입구 사진의 밝은 회색 외벽, 짙은 회색 하부, 청회색 계열 창유리와 밝은 창틀을 재질 참고로 사용했다. 주변 225개 건물에 적용한 창문 간격/크기/층별 배열과 하부 높이는 절차적 가정이다. 해당 225개 건물 각각의 실제 외관을 확보한 것은 아니다. 실외기, 외벽 무늬, 정확한 난간과 옥상 구조는 미재현이다.
- 도로 원본 1,631개 구간 중 `width` 태그 0개, `lanes` 태그 23개, `surface` 태그 108개를 확인했다. `scene.json`에 원본 ID/이름/태그와 폭 가정의 출처를 보존한다. 길 이름만으로 실제 폭을 확인했다고 판단하지 않는다.
- 1,595개 구간에 도로/보행 면을 생성한다. 예를 들어 residential은 6m, service는 4m, footway는 1.8m, 차로 수가 있으면 차로당 3m + 0.5m로 가정한다. 이는 설계 기준이나 현장 측정치가 아닌 시각화 기본값이다. 전체 규칙은 `src/road-data.js`에 있다.
- 지도에 기록된 보행로와 marked crossing에만 별도 보행 면/횡단 표시를 그린다. 중앙선은 원본에 차로 수와 `lane_markings=yes`가 있는 양방향 구간에 한정한다. 표시 폭/간격은 추정이다. 교량, 터널, 면형 보행 공간 등 지원하지 않는 36개 구간은 지면 도로로 왜곡하지 않고 생략한다.
- 도로는 3m 이하 간격으로 세분화하고 렌더링 지형 삼각형 높이에 맞춘다. 이는 지형 자료의 해상도를 높인 것이 아니다. 단차/옹벽/횡단 경사/교차로 형상은 여전히 미검증이다. 사진의 도로를 별도 배경 그림으로 붙이지 않고 기존 지도 좌표와 층간 시차를 유지한다.
- 시점은 여전히 외벽 밖 0.8m 후보 위치다. 실내와 창 개구부를 연결하지 않았으며 이 한계를 화면에 표시한다. 1.5m는 사용자가 제시한 관찰 높이 기본값이지 인체 평균에 대한 검증 결과가 아니다.

## 건물 식별과 Google Earth 대조

- `scripts/building-names.mjs`가 같은 OSM XML 스냅샷의 이름과 주거 부지 외곽을 읽는다. 일반 건물의 이름은 원본 `name` 그대로 사용한다. 이름 없는 건물에는 `이름 미확인 #OSM_ID`를 표시한다. 숫자 동 이름은 꼭짓점 80% 이상이 하나의 이름 있는 주거 부지에 포함될 때만 단지명을 붙이며, 이름 출처를 `osm-name-and-site-containment`로 분리한다.
- 부지 추정에는 폐합된 way 또는 inner ring 없는 multipolygon의 폐합된 outer way만 사용한다. 여러 열린 외곽을 임의 연결하거나 모호한 복수 부지를 선택하지 않는다. 신촌푸르지오 부지 way 463988053, e편한세상 신촌 부지 relation 20733682가 로컬 원본에 있다. 이 연결은 실측 또는 사진 대조 결과가 아니다.
- 현재 시야의 건물 표시는 렌더링과 같은 원본 외곽/높이로 만든 개별 picking mesh의 광선 교차에 기반한다. 화면의 표본 위치에서 발견한 건물 중 겹치지 않는 최대 6개 이름을 각 층에 표시한다. 모든 건물이 동시에 표시되는 것은 아니며, 표시되지 않은 건물도 3D 표면 또는 대조 지도에서 클릭 조회할 수 있다. 지형/가정 건물 숨김 상태를 반영한다.
- 조회에는 원본 ID, 이름 근거, 높이 태그/층수 환산/용도 가정의 구분과 OSM 원본 링크가 있다. 신촌푸르지오로 부지 연결된 207동(902872241), 208동(902872243), 210동(902872238)은 높이 태그가 없어 모두 기존 15m 가정이다. 이름을 붙였다고 높이가 검증되거나 보정된 것은 아니다.
- 도로 대조 지도는 같은 OSM 경로를 위에서 보여준다. 선택 도로의 최근접 중심선 지점으로 카메라를 회전하고, 현재 모델에서 해당 한 점을 가리는 건물/지형을 표시한다. 도로 전체의 가시 면적이나 실제 조망 판정이 아니다. 선택 경로를 주황색으로 강조해도 가림을 무시하지 않는다. 실제 도로 폭/옹벽/새 도로 정합은 여전히 미검증이다.

Google 공식 문서 확인:

1. [Maps URLs](https://developers.google.com/maps/documentation/urls/get-started): API 키 없는 외부 위성지도/Street View 링크를 사용한다. Street View `viewpoint`는 가장 가까운 촬영점으로 이동할 수 있으므로 세대의 높이/정확한 좌표/화각 일치를 보장하지 않는다.
2. [KML Reference](https://developers.google.com/kml/documentation/kmlreference): 현재 두 층 Camera의 위경도/절대표고/방위/tilt를 내보내고 주변 OSM 건물 외곽과 도로 중심선은 clampToGround로 내보낸다. DOM XML API로 작성하고 브라우저 다운로드 후 XML 파싱으로 구조를 검사했다. Earth와 DEM 기준 및 화각은 다를 수 있다.
3. [Photorealistic 3D Tiles](https://developers.google.com/maps/documentation/tile/3d-tiles): 앱 내부 실사 3D 표시의 공식 후보이며 API 키, 결제 설정, 이용조건/출처표시 준수가 필요하다. 현재 앱에는 API 키나 Google 타일을 연결하지 않았다.
4. [3D coverage](https://developers.google.com/maps/documentation/javascript/3d/coverage): 전 세계 지형과 지역별 3D surface의 지원 범위가 구분된다. 북아현동의 실사 건물 지원 여부는 확인하지 못했다.
5. [Google Geo Guidelines](https://about.google/brand-resource-center/products-and-services/geo-guidelines/): Earth 결과물의 3D 모델 재구성 제한 등이 있어 캡처를 추출해 자체 외벽 재질/모델로 만드는 방식은 적용하지 않았다.

이번 환경에서는 CUA 브라우저를 사용할 수 없었고 Earth URL의 웹 열람도 실패했다. 따라서 Google Earth 화면에서 실제 도로/건물을 대조하거나 KML을 직접 불러오는 검증은 수행하지 못했다. 완성된 부분은 로컬 앱의 건물 식별, 대조 지도, 외부 링크 생성, KML 내보내기이며 실사 지도 연동 완료로 표현하지 않는다.
