# 평면도 자산 점검 및 보완 (2026-09-20)

## 점검 범위와 결과

`scripts/audit-plan-assets.mjs`로 현재 저장된 KB 공급자 파일 전체 1,917개와 SH 증빙을 검사했다. 기존 서울 수집 큐의 공급자 1,914개와 집계 범위가 다르다.

| 항목 | 결과 |
| --- | ---: |
| 평면도 이미지가 있는 공급자 단지 | 880 |
| 공급자 세대수와 이미지 연결이 모두 일치하는 단지 | 296 |
| 동호수 중복 타입 충돌을 제외한 이미지 연결 세대 | 463,608 |
| 이미지가 없는 타입 | 6,861 |
| 공급자 세대수보다 동호수 기록이 부족한 단지 | 335 |
| 복수 타입이 연결된 동호수 | 2,215 (8개 단지) |
| 공급자 세대수보다 동호수 기록이 많은 단지 | 6 |

참조된 자산 4,840건은 SHA-256 일치와 실제 픽셀 디코딩을 통과했다. 서로 다른 이미지 해시는 4,760개이며 SH 증빙 자산 31건도 포함한다. SH 자산에는 배치도 등도 있어 모두 세대 평면도라는 뜻은 아니다. 이미지가 없는 타입은 공급자에 이미지가 없던 경우도 포함하며 다운로드 실패로 단정하지 않는다.

기존 수집 요약의 465,632세대와 이번 463,608세대는 범위 및 충돌 제외 기준이 다르다. 차이를 파일 유실 세대수로 해석하지 않는다. 공급자 기준 연결 완료는 현장 검증이나 실제 창 방향·높이·뷰 모델 완성을 뜻하지 않는다.

## 다음 보완 대상

`missing-types.csv`는 공급자 타입별 세대수가 큰 순서로 정렬했다. 우선 항목은 잠실엘스 84C(2,938), 은마 76(2,674), 파크리오 84C(1,978), 디에이치퍼스티어아이파크 84A(1,963), 올림픽선수기자촌 83(1,933)이다. 이 수치는 누락 타입의 공급자 세대수이며 보완 성공 세대수는 아니다.

같은 면적만으로 SH/LH 자료를 다른 단지나 타입에 자동 대입하지 않는다. 주소·단지·타입·동호수표 증빙을 함께 확인해야 한다. 이번 작업은 기존 자료 감사와 LH 원본 1건 복구까지이며 전체 누락 타입을 새로 수집한 작업은 아니다.

감사 스크립트는 로컬 자료만 읽는다. 앱 갱신 스크립트는 공급자별 타입 및 첫 동호수 레코드를 인덱싱하도록 개선했으며, 기존 타입 선택 순서와 충돌 보존 동작을 유지한다.

## 검증 및 앱 반영 제한

- Playwright로 검토 화면을 열어 전체 1,917개, 이미지 보유 880개, 충돌 8개 단지 필터를 확인했다. 브라우저 스크립트 오류는 없었다.
- 단위 연결/커버리지 테스트 14개, 주택대장 보정 테스트 5개, SH 보정 테스트 3개가 통과했다. 정규화된 중복 동호수 후보를 제거하면서 다른 단지의 기록과 순서를 보존하는 회귀 검증을 추가했다.
- 전체 빌드 통합 테스트는 실패했다. 최신 공급자 동호수 1,035,319개를 포함한 카탈로그를 `JSON.stringify(value,null,2)`로 저장하는 단계에서 `RangeError: Invalid string length`가 발생했다. 두 번째 빌드의 결정성 검증에는 도달하지 못했다.
- 기존 `catalog.json`은 531,828,307바이트, 2026-09-13 생성본 그대로 유지됐다. 최신 880개 단지를 앱 전체 검색에 반영했다고 해석하면 안 된다. LH 원본 파일은 복구됐지만 기존 카탈로그의 availability 값도 아직 갱신되지 않았다.
- 다음 구현 작업은 카탈로그의 단지별 분할 저장 및 이를 읽는 앱 경로 변경이다. 쓰기만 분할하고 읽기에서 다시 하나의 거대한 문자열로 합치는 방식은 같은 한도를 재발시킨다.
