# 국토위성 아파트 영역 수집

`scripts/collect-cas-imagery.mjs`는 국토정보맵의 공개 위성정사영상 목록을 검색하고,
아파트 주변에 필요한 장면을 선정한 뒤 기존 간편인증/InnORIX 전송 흐름으로 신청한다.
GPT/이미지 생성/비전 API를 사용하지 않는다. 앱 배경 교체와 타일 생성은 별도 단계다.

## 실행

```powershell
node scripts/collect-cas-imagery.mjs --inventory --plan --targets research/seoul/raw/apartments.json --inbox C:\Users\User\Downloads\satellite_01
node scripts/collect-cas-imagery.mjs --plan --rgb-preview --inbox C:\Users\User\Downloads\satellite_01
node scripts/collect-cas-imagery.mjs --download --inbox C:\Users\User\Downloads\satellite_01
node scripts/collect-cas-imagery.mjs --status --inbox C:\Users\User\Downloads\satellite_01
```

첫 명령은 영상 목록과 수집 계획만 만든다. TIFF를 다운로드하지 않는다.
`.tools/cas-imagery/review.html`, `summary.json`, `plan.json`에서 계획과 빈틈을 확인한다.
`--download`는 별도 Chrome 프로필을 사용한다. 간편인증과 첫 신청서의 사용 목적·동의는
사용자가 입력한다. 이후 입력은 페이지 메모리에서만 재사용한다. 생년월일·인증 토큰을 파일에 기록하지 않는다.
영상당 RGB PS 3개 밴드만 선택하고 사이트 코드가 XML을 추가한다. 선택 항목이 일치하지 않으면 신청을 중단한다.
외부 전송 프로그램의 저장 위치를 `--inbox`와 같게 지정해야 한다.
웹 전송 팝업에서 요청한 RGB PS 파일 목록이 확인되면 전체 다운로드를 누른다.
별도 Windows 전송 프로그램 내부의 버튼·저장 경로는 이 도구가 조작하지 않는다. 해당 UI에서는 수동 조작이 필요할 수 있다.

## 전국 입력

### 다음 수집 순서 (사용자 지시, 2026-09-18)

전국 확장용 실행 코드와 지역별 작업 생성은 [전국 수집 계획](NATIONAL-COLLECTION-PLAN.md)에 구현했다. `scripts/national-collection.mjs`로 목록 조회·준비·실행·상태 확인을 수행한다. 자동 상주 전환은 하지 않으며 서울 완료를 확인한 뒤 다운로드 단계가 열린다.

현재 서울 영상 계획을 마친 뒤 광역시별로 위성 영상을 수집한다. 대상은 부산·대구·인천·광주·대전·울산이며 도시 간 우선순위는 아직 정하지 않았다. 각 도시의 대상 좌표 목록과 영상 계획·전송 상태를 별도 폴더로 관리한다. 현재 실행 중인 서울 계획은 변경하지 않는다. 이 기록은 후속 작업 지시이며 광역시 자동 전환이 구현·예약됐다는 의미는 아니다. 광역시별 대상 좌표 확보와 영상 목록 선정이 선행되어야 한다.

현재 전국 확보 완료인 자료는 OSM 한국 추출본이며, 별도 가공 완료 범위는 길 데이터다. 국토지리정보원 수치지도 1:1000의 현 로컬 수집 목록은 서울 25개 구 대상 2,488건으로 전국 수치지도 확보 완료와 구별한다.

기본 제공 목록은 **서울의 확보된 단지 목록**이다. 전국 좌표 목록을 확보했다는 의미가 아니다.
전국 아파트 좌표를 아래 JSON 또는 GeoJSON Point로 넘기면 전국에 동일한 알고리즘을 적용한다.
폴리곤·CSV·주소만 있는 자료는 입력 전에 좌표로 정규화해야 한다.

```json
[{"id":"stable-complex-id","name":"아파트명","point":[127.0,37.5]}]
```

```powershell
node scripts/collect-cas-imagery.mjs --inventory --plan --targets apartments-national.json --state .tools/cas-national --max-gb 300 --max-scenes 100
```

ID 중복, 좌표 누락, 한국 범위를 벗어난 좌표는 `rejectedTargets`에 남긴다. 새 전국 단지 목록 수집·주소 지오코딩은 이 도구가 자동 수행하지 않는다.
기본 아파트 중심 ±300m를 격자로 덮는다. 이는 실제 단지 경계를 대신하는 명시적인 가정이며 큰 단지는 `--radius`를 늘려야 한다.

## 영상 선정과 비용

- 위성정사영상 L2G만 사용. ARD/모자이크와 중복 요청하지 않는다.
- 아파트가 있는 지역만 공개 목록 검색. 499건 이상이면 기간을 분할해 누락을 줄인다.
- 기본 운량은 0, 예상 태양 고도 40도 이상, roll/pitch 절댓값은 각각 20도 이하.
- 태양 고도는 카탈로그 ID의 UTC 시각에서 계산한 근사치다. 검색 응답의 날짜 자정은 쓰지 않는다.
- 메타데이터 모드는 각 격자의 최고 품질 후보에서 품질 점수 20% 이내인 후보만 허용한 뒤, 추가 커버 격자 수 × 품질 / 예상 GB로 탐욕 선택한다. 전역 최적해는 보장하지 않는다.
- 촬영 기울기는 건물 측면 노출을 줄이기 위한 보조 지표다. 오래된 영상이 선택될 수 있으므로 촬영일을 계획에 표시한다.
- RGB PS + XML만 수집. 현재 샘플은 약 5.62GB이며 목록에는 확정 파일 크기가 없어 장면당 6GB를 예약한다. `--max-gb`는 추정치 예산이며 실제 다운로드 바이트 상한이 아니다.
- 기존 3개 TIFF+XML 헤더 검증을 통과한 영상은 신규 다운로드 비용을 0으로 취급한다.

사용자 예산에 따라 기본 용량은 **1,000GB(십진 1TB)**, 최대 166장으로 변경했다.
`--rgb-preview`는 메타데이터 기준을 통과한 후보의 사이트 컬러 미리보기를 받아 비교한다.
동일 격자를 EPSG:5179 좌표로 찾아 RGB 휘도 중간값과 하위 10% 밝기, 어두운 픽셀 비율, 밝게 포화된 픽셀 비율로 점수를 계산한다.
유효 픽셀 98% 미만의 격자는 제외한다. 각 격자의 최고 점수 장면만 허용하며, 단지마다 다른 영상이 선택될 수 있다.
계획의 `newCells`는 해당 영상이 배정된 격자다. 이후 타일화에서도 이 배정을 따라야 한다.
미리보기는 공급자가 이미 밝기를 조정한 8비트 이미지이며, 원본 RGB PS를 동일한 방식으로 합성한 결과는 아니다.
안개·눈·밝은 지붕·수면과 그림자를 정확히 분류하는 모델은 없으므로 이것은 밝기 후보 선정용 지표다.
미리보기 미제공·검은 여백·품질 미달은 커버되지 않은 상태로 남긴다. 새 후보를 추가하면 같은 명령으로 재평가한다.

**운량 0은 그림자 0이 아니다.** 태양 고도·기울기로 위험을 줄일 뿐, 건물별 그림자·눈·계절 색상·가려짐을 판정하지 않는다.
카탈로그 모서리는 검은 여백을 포함할 수 있다. 계획상의 커버와 실제 유효 픽셀 커버를 구분하며
전송 후 타일화 단계에서 NoData 마스크 검사·대체 후보 재선정이 필요하다.
전국 전부 수집 완료 또는 무그림자 최적 영상을 보장한다고 표시하지 않는다.

## 중단과 검증

`Ctrl+C` 또는 상태 폴더에 `STOP` 파일을 만들면 중단한다. 재개 전 `STOP`을 제거한다.
잠금과 원자적 JSON 저장을 사용한다. `requested`는 자동 재신청하지 않고 기존 파일을 기다린다.
타임아웃은 `review`; `--retry-review`가 있을 때만 재신청한다.
인증/전송 오류 후 브라우저는 사용자가 닫거나 Ctrl+C로 종료할 때까지 유지한다.
인증을 다시 받으면 신청서 메모리는 사라져 최초 입력을 다시 해야 한다.

`verify-cas-files.py`는 Python 표준 라이브러리만 사용한다. XML ID/밴드, TIFF 헤더 크기/16비트/비압축 형식,
파일 길이를 확인한다. 대용량 픽셀·전체 해시는 읽지 않는다. 상태명 `downloaded-header-checked`는
픽셀 무결성·지리 정합·타일 생성 완료를 뜻하지 않는다. 입력 TIFF/로그인 세션/수집 상태는 Git에 올리지 않는다.

사이트 응답 구조는 2026-09-14 공개 페이지에서 확인했다. 로그인 후 실제 주문·외부 전송은 사용자 세션에서 별도로 확인해야 한다.

2026-09-14 첫 실제 신청/InnORIX 전송을 확인했다. 장식 요소가 입력을 가리는 문제는 native click과 상태 검증으로 수정했다.
신청서 입력은 기존 인증 창에서 복구해 메모리에만 보관했다. 실제 전송 팝업 `nlippd.ngii.go.kr`도 같은 opener와 파일 목록 검증을 거친다.
`--wait-minutes`는 전송 진행량이 늘지 않는 대기 시간으로 적용한다. 진행 중인 느린 다운로드는 시간이 지났다는 이유로 중단하지 않는다.
전송이 멈추면 다음 신청을 겹쳐 열지 않고 보류한다. 전체 20장 연속 완료 검증은 아직 진행 중이다.

2026-09-15 첫 5.24GB 영상의 RGB PS+XML 다운로드 및 헤더 검증이 완료됐다.
다음 신청에서 로그인 만료 처리가 빠져 멈춘 문제를 수정했다. 매 신청 전 세션을 검사하고,
만료 시 `awaiting-login`으로 저장하여 사용자의 재인증을 기다린다. 전송 중에는 5분마다 세션 상태를 확인한다.
이는 사이트의 강제 만료나 간편인증을 우회하지 않는다. 페이지가 새로 로드되면 메모리상의 신청서도 초기화되어 최초 입력이 다시 필요할 수 있다.

사용자 요청에 따라 작업 브라우저에는 별도로 60초 간격의 세션 확인과 브라우저 내부 마우스 이동을 적용했다.
OS 마우스 커서·클릭·새로고침·폼 입력은 건드리지 않는다. `session-activity.json`에 마지막 실행 시각과 인증 상태만 저장한다.
로그아웃된 상태에서는 세션 확인만 수행한다. 사이트의 고정 만료 시간을 없애거나 재인증을 자동으로 수행하지는 않는다.

## 최초 실행 결과 (2026-09-14)

서울 목록에서 좌표가 있는 2,805개 단지, 좌표 누락 29개를 구분했다.
공개 목록은 기간 분할 44회로 조회했고 L2G 후보 194개를 확보했다.
기본 품질 기준에서 9장/RGB PS+XML 약 54GB를 선정했다.
요청 격자 10,552개 중 9,972개가 계획상 포함되며, 주변 영역에 빈틈이 남은 단지는 166개다.
이 수치는 서울 전체/전국 아파트 전체 또는 유효 픽셀 커버 검증 완료를 뜻하지 않는다.
대용량 TIFF 신청은 실행하지 않았다. 현재 갖고 있는 2021년 샘플의 RGB PS+XML은 헤더 검증을 통과했다.

1TB 예산과 RGB 미리보기 비교를 적용한 후에는 컬러 미리보기 46개(약 65MB)를 분석했고,
5개는 빈 응답으로 비교하지 못했다. 아파트 유효 픽셀을 가진 후보 21개 중 구역별 최고 점수를 배정하여
20장, 약 120GB를 선정했다. 계획 격자는 9,495/10,552개이며 379개 단지 주변에 빈틈이 남는다.
메타데이터만 쓴 이전 계획보다 미완료가 늘어난 것은 미리보기 미제공과 유효 픽셀 검사도 적용했기 때문이다.
이 결과는 고해상도 원본을 동일한 톤으로 합성한 최종 비교가 아니다. TIFF 다운로드는 실행하지 않았다.
