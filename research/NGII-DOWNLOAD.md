# 서울 수치지도 2.0 수집기

서울 25개 구의 **수치지도 2.0, 1:1,000** 목록을 만들고 100개씩 다운로드 신청한다. 간편인증은 사용자가 작업용 브라우저에서 직접 완료한다.

```powershell
npm run collect:mapinfo
```

Windows에서는 설치된 Microsoft Edge를 사용한다. Chrome은 `--channel chrome`, Playwright Chromium은 `--channel chromium`으로 선택한다. Chromium이 없다면 `npx playwright install chromium`을 먼저 실행한다. Node 24 이상이 필요하다.

## 처음 실행할 때

1. 새로 열린 작업용 브라우저에서 간편인증 로그인을 완료한다. 평소 사용하는 브라우저의 로그인 상태를 가져오지 않는다.
2. 첫 신청서에서 사용 목적, 필요한 입력과 준수사항을 확인하고 **다운로드**를 누른다. 같은 실행 중 다음 신청서는 이 입력을 브라우저 메모리에서 재사용한다.
3. 외부 다운로드 프로그램이 나타나면 설치/실행 안내를 처리하고 **저장 폴더를 `C:\Users\User\zipview\mapinfo`로 지정**한다. ZIP과 XML을 함께 저장한다. 수집기는 그 폴더를 확인한다.

프로그램이 기본 다운로드 폴더에 `down_260913_01` 같은 폴더를 생성해도 된다. `%USERPROFILE%\Downloads\down_*` 안에서 동일 도엽의 ZIP/XML 쌍을 검증해 `mapinfo`로 복사하고 다음 묶음을 진행한다. 원본은 유지한다. 다운로드 루트를 바꿨다면 `--inbox D:\Downloads`를 지정한다.

이미 실행 중인 이전 수집기를 재시작하지 않고 이 감시 기능을 추가하려면 별도 터미널에서 `npm run import:mapinfo -- --watch`를 실행한다. 이 보조 프로세스는 파일만 가져오며 수집 상태는 기존 수집기 하나만 갱신한다.

첫 신청서 입력을 마친 이후에도 마지막 버튼을 직접 눌러야 하는 경우, Windows에서 아래 보조 프로그램을 실행한다. 이미 열려 있는 작업용 Chrome에 Windows 접근성 기능으로 연결하므로 로그인 창을 다시 열지 않는다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/watch-ngii-ui.ps1
```

최신 수집기는 신청서 입력·동의 선택이 1초 동안 유지되는지 확인한 후 자동 제출한다. 이 버전에서는 보조 프로그램에 `-TransferOnly`를 붙여 전송 창만 처리하도록 권장한다. 두 프로그램이 같은 신청 버튼을 중복 클릭하는 일을 방지한다.

작업용 Chrome 프로필의 창만 대상으로 신청서의 마지막 `다운로드`, 파일 전송 창의 `전체 다운로드`/시작 버튼을 처리한다. 현재 요청한 도엽 목록과 전송 창의 목록을 대조하고, 전송 중인 창과 이미 처리한 묶음은 다시 누르지 않는다. 일반 Chrome 창, 인증·동의 입력, 폴더 선택, 오류 확인 버튼은 조작하지 않는다. 처음 지정한 `Downloads\down_260913_02` 폴더를 계속 사용해도 된다. 작업용 Chrome이 여러 개라면 `-ChromeProcessId`로 하나를 지정한다.

`-Once -DryRun`은 클릭 없이 현재 처리할 버튼이 있는지만 확인한다. 동시 실행 방지를 위한 `ui-watch.lock`이 남았다면 기존 보조 프로그램이 종료됐는지 확인 후 그 파일만 제거한다.

공개 목록 조회에는 로그인이 필요 없다. 실행 시 저장된 목록이 없으면 25개 구를 먼저 조회한다. 실행 중인 터미널과 작업 브라우저를 유지한다.

## 자동으로 처리하는 부분

- 구별 수치지도 V2의 서버 집계와 실제 목록 개수를 비교하고, 1:1,000 도엽을 추린다. 목록이 500개에 도달하거나 개수가 맞지 않으면 누락 가능성으로 중단한다.
- 경계에 걸쳐 여러 구에 나타나는 동일 도엽을 중복 제거한다. 서버가 기본으로 반환하는 최신 이력을 사용한다. 구마다 같은 도엽의 제작연도/고시/이력이 다르면 중단한다.
- 기존 ZIP/XML을 확인하여 같은 도엽·축척·종류·제작연도·고시·이력·도엽명이 일치하는 자료를 건너뛴다. 검색 레이어의 OBJECTID와 XML의 지도순번은 서로 다른 식별자이므로 비교하지 않는다.
- 이름만 다르면 ZIP의 각 SHP/PRJ 좌표 범위를 EPSG:5179로 변환해 공식 도엽 범위와 비교한다. 네 경계의 최대 오차가 2m 이하이고 나머지 메타데이터가 일치할 때만 통과시키며, 좌표 범위·오차·SHA-256을 상태 파일에 기록한다. 단순 영역 겹침이나 중심점 일치만으로 통과시키지 않는다. Python의 pyproj가 필요하며 기존 `.tools/mapinfo-python` 환경을 우선 사용한다.
- 좌표 불일치, 좌표 조회/변환 실패, 다른 메타데이터 불일치는 `review`로 보류한다. 원본 ZIP/XML과 검토 사유를 남기고 다음 묶음을 진행하며, 보류 자료를 검증 완료 수에 포함하지 않는다. 원본 XML의 이름을 수정하지 않는다.
- 구리시 등 일부 경계 도엽의 ISO 19115 XML도 지원한다. 자료 식별 인용문의 도엽번호·1:1,000 축척·제작년도·고시번호와 수치지도 2.0 지형지물속성목록을 확인한다. 이 형식은 기존 도엽명/이력 필드가 없어 최신 이력(`0`) 요청에만 적용하며, 촬영년도나 일반 제목 문자열로 대체 판정하지 않는다. 원본 XML은 수정하지 않는다.
- 신청을 최대 100개씩 나누고, 사이트의 정상 신청 함수를 사용한다. 첫 신청서 작성 이후에는 같은 입력으로 다음 묶음을 신청한다.
- 일반 브라우저 다운로드는 지정 폴더로 저장한다. 전송 팝업에 유일한 `전체 다운로드` 버튼이 있으면 누른다. 외부 프로그램의 파일도 같은 폴더에서 감지한다.
- ZIP의 모든 항목을 읽어 CRC/길이를 검사하고, SHP·SHX·DBF·PRJ 레이어 구성이 있는지 확인한다. SHA-256도 기록한다. 신청 접수나 전송 팝업 표시만으로 완료 처리하지 않는다.
- 이미 검증한 파일이 삭제되거나 손상되면 다시 미완료로 처리한다. 다음 묶음을 신청하기 전에 로그인 만료를 확인한다.

## 중단과 재개

`Ctrl+C` 후 같은 명령으로 재개한다. 요청 전에는 `pending`, 요청 준비 이후에는 `requested`, 실제 파일 검증 이후에는 `verified`로 저장한다. 미완료 신청이 있으면 먼저 해당 파일을 기다린다. 사이트의 신청 내역에서 기존 다운로드를 다시 열 수 있다.

간편인증 중 부모 페이지가 새로고침되거나 리다이렉트되면 로그인 상태를 다시 확인하고 지도 스크립트가 준비될 때까지 기다린다. 그 밖의 오류로 자동 처리가 멈추더라도 실행 중인 작업 창은 자동으로 닫지 않는다. 오류를 확인한 뒤 창을 닫거나 `Ctrl+C`로 종료한다.

신청서 초기화 스크립트가 늦게 동의를 해제하거나 필드를 비워도 저장한 입력을 다시 복원한다. 동의 라디오에는 클릭 이벤트를 발생시키고 실제 선택 상태를 확인한다. 브라우저 메모리에 사용자 입력이 없는 첫 신청서는 계속 직접 확인한다. Windows의 일시적인 상태 파일 공유 충돌은 기존 파일을 유지한 채 저장을 재시도하며, 접근성 보조 프로그램은 파일 교체를 허용하는 읽기 모드로 상태를 확인한다.

신청 도중 종료된 경우 서버가 신청을 받았는지 확실하지 않을 수 있으므로 **자동으로 재신청하지 않는다**. 사이트 신청 내역을 확인한 뒤 재신청하려면 다음 명령을 사용한다.

```powershell
npm run collect:mapinfo -- --retry-pending
```

기본 대기 시간은 묶음당 60분이다. `--wait-minutes 180`으로 늘릴 수 있다. 시간 초과 자료는 `review`와 `transfer-timeout` 사유로 보존하고 다음 묶음을 진행한다. 다음 실행에서도 보류 자료는 재검증하지만 자동 재신청하지 않는다. `--retry-review`는 보류를 풀어 재검증하고, 아직 파일이 없으면 재신청을 허용한다. 검증에 다시 실패한 자료는 다시 보류된다. 실행 중인 프로세스를 강제 종료해 `.tools/ngii-downloads/run.lock`이 남았다면 다른 수집기가 실행 중이지 않은지 확인한 뒤 그 잠금 파일만 제거한다.

같은 이름의 파일을 덮어쓰지 않는다. 충돌 파일은 `.partial`로 보존하고 중단하므로, 기존 파일을 확인하여 별도 폴더로 옮기거나 파일명을 정리한 뒤 재개한다. 현재 자동 검증 대상은 SHP 묶음이다. NGI 형식만 제공되는 도엽은 별도 변환이 필요하며 완료 처리하지 않는다.

## 조회 명령

```powershell
npm run collect:mapinfo -- --inventory
npm run collect:mapinfo -- --status
npm run collect:mapinfo -- --refresh --batch-size 50
```

`--inventory`는 목록 조회와 기존 파일 검증만 수행한다. `--status`는 파일과 진행 상태를 확인하며, 이름 불일치 자료에 저장된 공식 좌표가 없으면 공개 좌표 조회를 수행할 수 있다. `--refresh`는 다운로드 전에 목록을 갱신한다. 조회 명령은 다른 수집기가 실행 중이지 않을 때 실행한다.

상태 파일은 `.tools/ngii-downloads/manifest.json`, 다운로드는 `mapinfo/`에 저장하며 Git에서 제외한다. `--state`, `--output`으로 바꿀 수 있다. 외부 프로그램도 같은 출력 폴더를 사용해야 한다.

브라우저 프로필은 `%LOCALAPPDATA%\Zipview\ngii-browser`에 따로 저장한다. Chrome은 `ngii-browser-chrome`을 사용해 Edge 프로필과 분리한다. 브라우저 자체가 로그인 세션을 유지할 수 있지만 수집기는 쿠키, 인증서, 인증 응답을 추출하지 않는다. 신청서 값은 해당 페이지 메모리에서만 재사용하며 로그/상태 파일에 기록하지 않는다. 새 실행이나 페이지 새로고침 후에는 신청서 확인이 다시 필요할 수 있다.

## 검증 결과와 남은 확인

2026-09-13 최초 공개 사이트 조회 결과: 서울 25개 구, 중복 제거 **2,488개 도엽**. 당시 기존 북아현동 **6개**의 XML/ZIP 검증 통과, 나머지 **2,482개**가 다운로드 대기 상태였다. 현재 진행 수치는 상태 파일에서 확인한다. 구 경계에 걸친 도엽을 포함한 사이트 검색 목록이며, 서울의 모든 지형 정보가 빠짐없이 존재한다는 공간적 정확도 검증은 아니다.

```powershell
node --test tests/ngii-files.test.mjs tests/ngii-inbox.test.mjs tests/ngii-coordinate-check.test.mjs
node tests/ngii-browser.mjs
node tests/ngii-login-navigation.mjs
powershell -NoProfile -ExecutionPolicy Bypass -File tests/ngii-ui-policy.ps1
```

브라우저 통합 테스트는 실제 공개 사이트 JS와 모달을 사용하지만, 로그인·신청 접수·전송 응답을 가짜 응답으로 교체한다. 실제 신청을 생성하지 않는다. 첫 입력 대기, 다음 묶음 자동 신청, 로그인 만료 후 재인증 대기, 팝업 버튼, 파일 저장 및 검증을 확인한다.

실제 간편인증 이후 INNORIX가 `Downloads\down_260913_02`에 여러 묶음을 저장하는 동작과 ZIP/XML 검증을 확인했다. 2026-09-13에는 접근성 보조 프로그램이 신청서의 마지막 다운로드 버튼을 누른 뒤 다음 100개 묶음의 파일 수신이 시작되는 것까지 확인했다. 처음 나타나는 폴더 선택이나 추가 인증·오류 확인은 직접 처리가 필요할 수 있다. 인식하지 못하는 전송 화면에서는 파일을 기다리고, 받지 못한 파일을 완료로 기록하지 않는다.

같은 날 도엽 `377052112`, `377052122`는 목록에서 성동2112/성동2122, XML에서 수원0129/수원0139로 표기되었다. 도엽 번호·제작연도·고시·이력 및 ZIP 검증이 일치하고 실제 좌표 범위와 공식 도엽 범위의 최대 오차가 각각 약 0.063m, 0.062m여서 좌표 보완 검증을 통과했다. 이 사례는 개별 번호 예외 목록이 아닌 공통 좌표 검증 코드로 처리한다.

2026-09-13 최종 수집 결과: 목록의 **2,488개 도엽 모두 검증 완료**, 대기·신청 중·검토 보류 0개. `mapinfo`에 고유 ZIP 2,488개와 대응 XML이 모두 존재하며 ZIP 합계는 525,461,304바이트다. 이름 불일치 2개는 위 좌표 보완 검증으로 통과했다. 마지막 82개 묶음까지 자동 신청·전송·검증 후 수집기와 UI 보조 프로그램이 종료됐다. 다운로드 원본은 기존 Downloads 폴더에 유지한다.

이 명령은 원본 수집까지 담당한다. 서울 전체의 원본을 Zipview의 각 단지 지형·건물 데이터로 변환하고 앱에 반영하는 단계는 별도다. 현재 `prepare-mapinfo.py` 등은 기존 단지 작업을 위한 코드이므로 서울 전체에 바로 실행하는 명령을 연결하지 않았다.
